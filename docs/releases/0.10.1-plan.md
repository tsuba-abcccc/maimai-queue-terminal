# maimai Q 0.10.1 详细开发计划

## 版本目标

本版本完成机台分组交互的收尾，并建立现场终端、队列网站和 QQ Bot 的版本状态视图。开发重点是修复问题和完成阶段性最终审查，不改变现场终端已经确认的排队、轮换、估时、特殊状态或撤销规则。

本版本同时作为 0.10.x 阶段的发布门槛：不能只以构建成功作为完成依据，必须覆盖日常流程、风险操作、状态组合、断网恢复、旧数据兼容和多端行为一致性。

## 三端版本状态

- “三端”固定指现场终端 App、队列网站和 QQ Bot，不把 API 服务端计入三端。
- 现场终端当前版本来自最近一次有效队列快照中的 `terminal.app_version`。快照不存在、字段缺失或终端从未同步时显示“未知”。
- QQ Bot 当前版本由现有身份心跳一并上报。旧 Bot 只上报 QQ 号时仍能成功，版本显示“未知”，不能影响菜单、通知或队列指令。
- 网站当前版本由网站部署流程通过受保护接口登记。浏览器只读取版本状态，不允许匿名访问者写入版本号，也不能把构建常量直接冒充服务器已经部署的版本。
- 服务端保存各端当前版本、最后上报时间和本次发布对应的最新版本；自建部署保持默认可用，不增加日常维护步骤。
- 版本比较按数字语义版本执行，不能使用字符串大小比较。状态固定为“已是最新版本”“有新版本”“高于公开版本”和“暂时无法确认”。
- 非法版本号、缺失版本号或无法比较时返回“暂时无法确认”，不能误报需要更新或已经最新。
- 新增独立版本查询接口，队列快照的高频刷新不额外触发文件读取、外部网络请求或写入。

## 网站与 QQ Bot 展示

- 网站在队列工具区域提供低干扰的“版本信息”入口，详情同时显示三端当前版本、最新版本、状态和最后更新时间。
- 网站版本接口失败时不影响队列加载、线上登记、自我标记或机台详情；入口保留并明确显示暂时无法获取。
- QQ Bot 主菜单增加“版本信息”，回复使用与网站相同的三端顺序和状态含义，不输出 `undefined`、空版本或内部枚举名。
- Bot 获取版本失败时只返回可执行的重试提示，不影响“查看队列”“查询人数”“加入排队”和“我的排队”。
- 所有对外名称继续使用“现场终端”“队列网站”“QQ Bot”，不在玩家提示中使用应用名作为功能称呼。

## 终端分组选择栏

- 首页存在两个及以上有效分组时，在队列区域底部显示可点击的分组选择栏；只有一个分组时不显示多余控件。
- 分组名称是页签。点击后使用分页动画切换，左右滑动仍由同一个 `PagerState` 控制；页签选中状态只读取实际页面状态，不能另存一份可能失步的索引。
- 30 秒无操作返回首页、新登记定位到所属分组、配置变化后的索引修正、手势滑动和点击页签全部通过同一个分页状态执行。
- 点击当前分组不重复播放动画。快速点击多个分组时以最后一次有效目标为准；配置变化导致目标失效时收敛到现有第一页或默认分组，不能越界或显示空页。
- 分组较多或名称较长时选择栏可横向滚动，当前项自动保持可见。点击区域不小于 48 dp，文字最多一行并使用省略号，不能挤压队列内容或右侧动态区域。
- 选择栏只改变可见分组，不修改终端默认分组、队列顺序、登记位置、估时、配置修订号、同步数据或审计日志。

## 网站双分组布局

- 网站恰好有两个有效分组时使用两列等宽布局，两个页签共同占满可用宽度并保持文字居中。
- 一个分组时继续隐藏切换栏；三个及以上分组继续横向滚动，不强制缩窄到不可读宽度。
- 长名称使用单行省略，完整名称保留在无障碍名称或提示中。桌面、窄屏、浅色和深色主题都不得出现偏移、溢出或选中态宽度跳动。
- 本项只改变分组导航布局，不改变当前分组、队列过滤、线上登记机台选择或 URL 行为。

## 数据迁移与兼容性

- 服务端启动时幂等创建或迁移版本记录字段；已有 `service_identity`、队列快照、玩家资料和历史事件不得丢失。
- 旧终端没有 `app_version`、旧 Bot 没有 `bot_version`、网站尚未登记部署版本时均正常提供队列服务，并把对应端显示为“未知”。
- 新 Bot 身份上报仍使用现有鉴权、超时和周期重试；失败后保留最近一次成功记录，不把临时断线错误写成版本降级。
- 版本查询是只读公开信息，不返回 API 密钥、服务器路径、提交凭据或其他部署秘密。
- 服务端先升级、三端后升级和三端先后不同步升级都必须可用；任何一端版本状态未知都不能阻断排队。

## 最终行为审查

- 队列核心：普通登记、固定组合、共同游玩预览、暂缓一次、待签到、暂时离开、未到场、退出、转移、拖动、本轮结束、仅结束本轮、进入游玩位置和撤销。
- 状态组合：特殊状态相互排斥或并存时的展示投影与真实队列，单人和双人机台，停机、恢复、营业时间、闭店收尾及关闭后重新开启登记。
- 远程入口：网站、移动设备登记和 QQ Bot 的可用条件、最终校验、幂等、重复提交、过期配置修订、回执、日志和通知。
- 同步恢复：断网、HTTP 错误、旧批次、另一终端实例占用、旧 schema 1 至 7 快照、应用重启和服务端先后升级。
- 多机台与分组：1、2、3、5、10 台机台，一个、两个和多个分组，默认分组删除、当前分组失效、新登记跨页定位以及 30 秒复位。
- 文案一致性：游玩位置、队列位置、暂缓一次、暂时离开、签到、线上登记、与服务端同步等既定术语；QQ 消息继续遵守空行和间隔点两侧不加空格的格式。

## 测试矩阵

- Android：全部 JVM 单元测试、队列长序列与随机行为测试、同步协议测试、Compose 分组点击与手势测试、lint、Debug 和签名 Release 构建。
- 服务端：全部 Python 测试，补充数据库迁移、旧上报、版本比较、鉴权写入、公开读取、失效值和三个端分别未知的测试。
- QQ Bot：全部测试，补充身份心跳版本字段、旧服务端兼容、版本信息格式、接口失败和主菜单顺序测试。
- 网站：构建、组件测试和 Playwright 行为测试，覆盖两分组等宽、三分组滚动、长名称、版本弹窗、接口失败、手机与桌面、浅色与深色主题。
- 集成：真实服务端启动后依次上传旧终端快照、新终端快照、旧 Bot 身份和新 Bot 身份，登记网站版本，再核对公开版本接口和三端展示。
- 风险回归：对所有会删除登记、改变位置、结束轮次或应用远程命令的入口进行一次成功、一次拒绝、一次重复提交和一次恢复后的行为核对。

## 发布门槛

- 所有已确认 P0/P1 必须修复并有回归测试；不能以“正常情况下大概不会发生”保留数据损坏、错误删登记或跨机台误操作。
- 较低风险问题尽量在本轮修复；确实不宜修改的项目必须说明场景、影响和暂缓原因。
- 新 UI 必须经过真实截图和交互检查，确认点击、滑动、动画、长文字、窄屏和主题表现，不做未经验证的整体视觉重构。
- 更新开发记录、README、版本号和玩家更新日志；前端改动同时推送网站仓库并按既定原子流程部署。
- 构建签名安装包，创建提交、完整 Tag、GitHub Release 和更新日志。发布失败时保留本地产物与可复核结果，不把未成功上传写成已发布。
