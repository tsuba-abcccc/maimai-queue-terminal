# maimai Q 0.12.3 公开测试版

maimai Q 0.12.3 修复网页玩家资料在分域部署和账户会话失效时的可见问题。部署者仍可使用自己的服务器、域名、数据库、网站和 QQ Bot，不依赖项目维护者服务器。

> 本版本仍处于 `0.x` 测试阶段。真实现场更新前应先备份终端数据和服务端 SQLite，并完成网站、Bot、终端与移动设备登记的联调。

## 本次更新

- 账户弹窗的现场命令状态轮询支持 `VITE_QUEUE_ONLINE_COMMAND_API_BASE`，与详情菜单和公开部署文档的分域 API 配置一致。
- 网页账户会话被撤销或过期时，自动清理旧账户、CSRF 令牌和个人队列状态，回到登录状态并提示重新登录。
- 命令状态接口返回会话失效时立即停止轮询，不再把过期账户继续显示为可操作状态。
- 不改变队列算法、现场终端规则、远程命令快照校验、闭店收尾、正常轮换、暂缓一次、暂时离开、待签到、固定组合、共同游玩预览、估时或机台容量规则。

## 下载文件

- `maimai-Q-0.12.3-terminal-beta.apk`：连接自建服务端的现场终端版。没有预置服务端地址或令牌，安装后由机厅管理员配置。
- `maimai-Q-0.12.3-local-beta.apk`：完全离线版，不申请联网权限，不提供网站或 Bot 同步。
- `public-site-0.12.3-beta.tar.gz`：独立公开队列页与网页玩家资料的静态文件。
- `koishi-plugin-maimai-q-0.3.13.tgz`：本版本配套的 Koishi 插件。
- `SHA256SUMS-0.12.3.txt`：全部发布附件的 SHA-256 校验值。

## 部署与更新

服务端、网站、Bot 和终端必须使用同一 Release。推荐更新顺序为服务端、网站、Bot、终端；每一步完成后再检查 `/queue-api-healthz`、网站版本详情、Bot 查询和终端同步。完整步骤见[公开测试版自建部署方案](../public-beta-deployment.md)。更新前必须备份 SQLite、`.env`、反向代理配置、Bot 配置、网站目录和终端数据。

## 验证范围

- 云服务端 144 项测试、Koishi Bot 80 项测试和公开网站 Vite 生产构建通过。
- 浏览器行为测试覆盖网页登录后打开本人登记、提交退出排队、二次确认，以及终端离线时阻止提交。
- 分域构建验证确认账户弹窗将命令状态请求发送到显式命令 API 地址。

## 已知边界

- 一个服务端实例仍只支持一个活动机厅和一台权威写入终端；多机厅与多终端同时联动尚未开放。
- 忘记网页密码时不允许在公共终端直接重置，当前需由管理员线下核验处理。
- 网站只能管理当前登录资料对应的本人登记，不能远程签到、结束本轮、调整他人登记、拖动顺序或修改终端设置。
- 当前不提供预构建 Docker 镜像，API 仍由部署者从固定 Tag 构建。
