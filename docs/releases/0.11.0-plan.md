# maimai Q 0.11.0 详细开发计划

## 版本目标

本版本建立后续多终端、多机厅和网页账户共同依赖的身份基础，并完成首次启动引导与六位玩家编号。它不开放多台终端同时写入，不改变登记、轮换、闭店收尾、暂缓一次、暂时离开、待签到、固定组合、共同游玩预览、估时或撤销规则。

现有实例必须无损升级。服务端先兼容旧终端，终端升级后继续使用原队列和玩家资料；任何身份迁移失败都只能让新增身份功能暂时不可用，不能阻断本地排队。

## 身份模型

### 机厅身份

- `venue_id` 是服务端分配的 UUID，仅用于协议、数据库关联和防止串厅，不要求用户记忆。
- `venue_code` 是服务端在自身范围内唯一的 8 位大写字母数字编号，用于界面核对和以后管理后台查找；排除容易混淆的 `0/O` 与 `1/I`。
- `venue_name` 是可修改的显示名称，不参与数据主键。改名不会创建新机厅，也不会改变队列、玩家资料或历史记录归属。
- 本地版生成本地 `venue_id`，但明确记录 `registration_state=LOCAL_ONLY`，不显示为已经在服务端注册。以后连接服务端时执行显式绑定，不直接把本地 ID 当作服务端 ID。
- 0.11.0 的一个服务实例仍只有一个活动机厅。数据库与接口使用机厅字段，但匿名公开接口继续返回该活动机厅，旧网站和旧 Bot 无需提供机厅参数。

### 终端身份

- 现有安装级 `X-Device-ID` 继续作为稳定终端 ID，不重新生成，不批量重写旧数据库字段。
- `X-Terminal-Instance-ID` 和代次继续表示一次应用运行实例，只用于防止重复实例同时同步，不能作为终端或机厅身份。
- 新协议额外携带 `venue_id`。服务端只接受已经绑定到该机厅的终端；0.10.2 及更早终端缺少该字段时，按当前单机厅兼容规则处理。
- 本版仍只有当前权威终端可以领取和完成远程命令。终端名称、默认机台分组和未来角色写入终端注册表，但不提前实现主从切换。

### 玩家身份

- 现有 UUID `profile_id` 仍是数据库主键，登记和历史关联不重写。
- 新增 `public_player_id`，格式固定为六位数字并保留前导零，用于玩家可见搜索和人工核对。
- 编号由服务端在共享玩家资料范围内保证唯一；本地创建时可先分配本地唯一编号，首次同步若发生跨端冲突，由服务端保留已存在编号并为后到资料分配新编号，再随资料修订同步回终端。
- 旧资料按稳定顺序幂等补号，同一数据库重复迁移结果不变。资料合并时保留规范资料的编号，旧编号记录为别名，不能重新指向其他玩家。
- 六位编号不是验证码、登录凭据或权限依据。网页风险操作仍不能仅凭该编号授权。

## 首次启动与升级流程

### 新安装

1. 欢迎页说明本地版与联网终端版的区别。
2. 联网终端填写服务端地址和同步令牌并测试连接；允许选择“暂时跳过”，跳过后按本地状态使用并可从设置继续。
3. 填写机厅显示名称。已连接服务端时提交注册并取得机厅 ID；未连接时创建本地身份。
4. 确认机台数量、机台配置、默认分组、营业时间和线上登记等现有必要设置。复杂项目进入原设置页，不在引导中复制完整编辑器。
5. 显示完成摘要，包括机厅名称、注册状态和终端名称，然后进入首页。

### 现有安装

- 以本机已经存在的队列状态、玩家资料或设置为依据识别旧安装，自动创建兼容安装记录，不覆盖任何现有数据，也不强制阻断首页。
- 已配置可用服务端的旧安装在后台查询当前单机厅身份并完成绑定；身份核对完成前暂停线上上传、私有资料恢复和远程操作，本地排队始终可用。服务端暂时离线时保留本地状态，恢复后再核对身份；只有明确确认旧服务端不支持身份接口时，才进入 schema 7 兼容模式，并在设置中显示“等待取得机厅身份”。未核对身份的服务端数据不得静默当作当前机厅数据。
- 无法可靠得知真实机厅名称时使用中性的待补充状态，不把域名、设备型号或机台备注猜作机厅名。首页保持可用，设置入口提示补充。
- 重新安装不是数据恢复方式。卸载清除本地终端身份的边界保持不变，本版本不会把服务器玩家资料同步宣传为整机恢复。

## 服务端与协议

- 同步 schema 从 7 升至 8，新增机厅对象、六位玩家编号和终端注册信息；继续完整接受 schema 1 至 7。
- 新增受终端令牌保护的安装信息接口，用于读取当前服务实例能力、注册或取得活动机厅、绑定终端以及更新非敏感显示名称。所有创建操作幂等。
- 数据库增加 `venue`、`registered_terminal` 和玩家编号别名结构；现有 `queue_snapshot.id=1`、`device_id` 范围和队列历史表暂不拆成多租户主键，避免在本版提前进行高风险全库重写。
- 当前快照增加 `venue_id`；服务端读取旧快照时补充活动机厅展示，但不伪造旧终端已经完成新版引导。
- 机厅不匹配返回稳定错误代码和明确原因，不得退化成 HTTP 500 或含糊的“同步失败”。旧客户端无法理解新错误时仍能看到可执行的中文说明。

## 各端表现

- 现场终端：欢迎引导、设置中的“机厅与终端”、应用详情和首页低干扰位置展示机厅名称；只有待补充或连接异常时才突出提醒。
- 网站：队列标题区域显示机厅名称和公开编号。一个机厅时不出现切换控件，为 0.14.0 预留结构化 `venue` 对象。
- QQ Bot：主菜单、查看队列和查询人数在已取得名称时显示机厅名称；通知正文只在区分来源有实际意义时增加机厅，不机械重复每一行。
- 玩家资料库：搜索同时支持昵称、QQ 和六位玩家编号；列表与详情以低干扰方式展示编号，长 UUID 不面向玩家显示。
- 文案统一使用“机厅”“现场终端”“机厅 ID”“玩家编号”，不混用门店、店铺、设备编号或资料 ID。

### 设置页信息架构

- 设置页改为左侧分类导航、右侧独立内容区和底部固定保存区，不再让全部设置堆叠在一条长页面中。
- 分类固定为“机厅与终端”“服务端与联动”“营业时间”“排队规则”“机台与分组”；纯本地版隐藏不适用的服务端分类。
- 切换分类保留整页草稿，所有修改仍在点击“保存设置”后统一生效；返回时继续确认是否放弃未保存内容。
- 机台数量、游玩容量、服务器切换和机厅重新绑定继续执行原有风险限制，界面重排不得绕过“关闭登记排队”或远程命令互斥校验。
- 左侧导航和右侧内容分别滚动，软键盘弹出时保留当前字段与底部保存区可见；Android 10 使用调整窗口尺寸的输入法布局配合 Compose 键盘边距。
- 本次只重组设置入口与保存交互，不修改闭店收尾、轮换、暂缓一次、暂时离开、待签到、固定组合、共同游玩预览、估时或撤销规则。

## 迁移与失败行为

- 数据库迁移必须在事务内幂等执行；启动失败时健康检查返回数据库结构未就绪，不能让半迁移服务接收写入。
- 为旧玩家补号前先检测现有冲突。任何单份异常资料只能阻止该资料补号，不能删除资料或阻断队列快照。
- 服务端先升级时，旧 App、网站和 Bot 行为不变；App 先升级连接旧服务端时降级为 schema 7，并把身份注册标记为待完成，不能反复生成不同机厅。
- 更换服务端地址属于身份边界变化。只在关闭登记且没有待处理远程命令时允许确认切换；普通网络错误不能被误判为更换服务端。
- 服务端返回不同 `venue_id` 时不得静默改绑。必须保留现有本地数据、停止线上写入并要求管理员确认，防止把一个机厅的队列上传到另一个机厅。

## 行为测试矩阵

- 新安装：本地版、联网版成功连接、连接失败后重试、跳过连接、应用在每一步退出并恢复、连续点击提交。
- 旧安装：空队列、正在排队、关闭登记、停机、有待签到登记、有待处理远程命令、旧 schema 1 至 7、已有测试/接管同步状态。
- 身份：重复注册、同一终端重复启动、终端 ID 保留、机厅改名、错误机厅 ID、旧服务端降级、服务端恢复、时钟偏差。
- 玩家编号：空库、500 份旧资料、前导零、碰撞、并发创建、云端与本地同号、资料合并、别名、搜索、移动设备登记、Bot 查询和日志关联。
- 跨端：终端、公开网站、移动登记页和 Bot 显示同一机厅名称；缺失名称、离线和旧快照均不出现 `null`、`undefined` 或错误机厅。
- 回归：完整运行现有队列核心、Android、服务端、Bot 和网站测试，重点复核同步、移动登记、资料补全、快速退出重入及运行实例冲突。

## 发布门槛

- 所有 P0/P1、跨机厅写入风险、资料编号错绑和旧数据丢失问题必须修复并增加回归测试。
- 真实旧数据库副本完成升级和回滚演练，升级前后队列 ID、登记、玩家 UUID、QQ、日志和设置逐项一致。
- 服务端必须先部署兼容版本并验证旧 0.10.2 终端仍可同步，再构建 0.11.0 终端包。
- 现场保数据覆盖包继续使用现场当前可覆盖的签名；公开 Release 使用长期正式证书。不能建议现场终端卸载或清除数据。
- 代码、README、部署文档、玩家更新日志、Tag 和 GitHub Release 完整发布；前端改动同步更新公开站点与其他独立站点。
