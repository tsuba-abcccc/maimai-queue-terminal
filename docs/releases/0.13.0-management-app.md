# maimai Q 0.13.0 管理后台

maimai Q 0.13.0 首先交付手机竖屏管理后台，并把管理命令接入现有单终端权威写入链路。它适合机厅工作人员在受控设备上查看和维护现场队列；玩家端网页、QQ Bot 和现场终端的既有权限边界不因此扩大。

> 本版本仍处于 `0.x` 测试阶段。真实现场安装前应备份终端数据、服务端 SQLite、环境文件和反向代理配置，并先用测试机验证管理命令回执。

## 本次更新

- 管理 App：手机竖屏、完整队列总览、线上登记立即签到、新建正式登记、任意登记编辑、机台转移、游玩偏好修改、暂缓/暂离/退出和等待顺序调整。
- 玩家资料库：查看私有资料、编辑昵称/性别/默认偏好/QQ 显示范围/终端编辑策略；对已绑定网页账户的玩家修改密码并撤销旧网页会话。
- 终端敏感策略：管理后台可以接管当前终端支持的线上登记、暂缓、暂离和 QQ Bot 联动策略。接管后现场终端不能编辑这些策略。
- 排版修复：玩家资料库和资料确认详情在手机宽度下使用稳定头像框、统一行高和间距，昵称过长时不会挤压性别标识；资料库列数随可用宽度调整。
- 服务端：独立 `QUEUE_MANAGEMENT_TOKEN`、管理 API 路由、幂等命令、快照上下文校验、稳定机台身份/配置修订校验和管理来源审计。

## 下载与安全

- `maimai-Q-0.13.0-management.apk`：不预置服务端地址或管理令牌的管理 Release APK，安装后在设置页填写。
- `maimai-Q-0.13.0-local-beta.apk`：完全离线的本地 Release APK，不申请联网权限。
- `maimai-Q-0.13.0-terminal-beta.apk`：不预置同步地址或终端令牌的现场终端 Release APK，安装后由管理员配置。
- `maimai-Q-0.13.0-management-test.apk`：受控 Debug 测试包，预置现场管理地址和令牌，只能交给指定测试人员，不得上传公开仓库或公开 Release。

公开 Release APK 已使用自 0.7.0 起的长期证书签名，证书 SHA-256 指纹为 `daa2e919d2f8d956c0a93417aae601e6ec658edc5ae7c9673830c53f649ec925`。公开包的服务端地址、终端同步令牌和管理令牌均为空；正式附件必须同时使用随 Release 提供的 `SHA256SUMS-0.13.0.txt` 校验。签名材料只保存在发布者的受控目录，不进入仓库或公开附件。

管理令牌是高权限凭据，必须与 `QUEUE_SYNC_TOKEN` 和 `QUEUE_BOT_TOKEN` 不同，长度至少 32 个 UTF-8 字节。令牌泄露后立即生成新令牌并重启 `maimai-queue-status`；旧测试包随即失效。

## 部署

服务端先部署 `cloud-server/app.py`、`requirements.txt` 和 `QUEUE_MANAGEMENT_TOKEN`，再重载 Nginx 的 `/api/queue-management/` 路由。部署后检查：

```bash
curl -i https://your-domain.example/queue-api-healthz
curl -i -H "Authorization: Bearer <QUEUE_MANAGEMENT_TOKEN>" \
  https://your-domain.example/api/queue-management/overview
```

无 `Authorization` 或令牌错误应返回 `401`；正确令牌且现场终端已上传 schema 8 快照时返回 `200`。管理 App 不直接写队列快照，现场终端离线时命令会等待或被拒绝并显示原因。

## 已知边界与后续

- 当前仍只有一台权威写入现场终端，不支持多终端同时写入；多终端联动留在后续版本。
- 管理后台尚未覆盖终端所有设置。完整机台配置、营业时间、同步故障恢复、日志浏览和其他未接入设置会在后续管理版本实现；本版本不把这些入口标记为已开放。
- 正常拖动全队列排序是日常队列操作，不属于敏感设置。即使绑定管理后台，现场终端的正常拖动排序仍保持可用；游玩位置继续按既有规则锁定。
- 尚未有连接真机/模拟器的 UI 自动化截图验收；发布前仍需在目标手机上人工确认竖屏滚动、长昵称、资料编号和头像间距。
