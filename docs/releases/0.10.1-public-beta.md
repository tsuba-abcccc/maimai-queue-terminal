# maimai Q 0.10.1 公开测试版

maimai Q 现以公开测试形式提供完整自建部署。部署者需要使用自己的 Linux 主机、域名、HTTPS、数据库卷和 QQ Bot，不依赖项目维护者服务器。

> 本版本仍处于 `0.x` 测试阶段。用于真实现场前，请先完成备份、恢复和完整联调，并安排能够处理误操作与机台故障的现场人员。

## 本次更新

- 修复服务端能力状态拆分，终端离线、关闭 QQ Bot 联动或关闭线上登记时，不再混淆已有登记管理与新增线上登记能力。
- 修复旧玩家资料别名尚未同步 QQ 时，网站和 Bot 显示空 QQ、提交后才失败的问题。
- 关闭“与服务端同步”后，终端会持久化关闭状态并在网络恢复或应用重启后继续确认，不再让服务端长期保留错误在线状态。
- 增加现场终端、队列网站和 QQ Bot 的版本状态；Bot 新增“查询人数”。
- 修复远程命令在机台删除或重编号后可能作用到错误展示编号的风险，并修复未发生有效拖动时仍提交顺序的问题。
- 终端增加可点击机台分组栏，网站双分组改为等宽展示。
- 新增不依赖其他站点的 `public-site/` 独立队列页；其他站点可以按自身构建流程复用队列组件。
- 公开构建不再预置维护者域名、服务器地址或令牌；Koishi 和服务端部署配置改为由部署者显式填写。

完整累计更新见[项目更新日志](https://github.com/tsuba-abcccc/maimai-queue-terminal/blob/v0.10.1/docs/update.md)，自建步骤见[公开测试版自建部署方案](https://github.com/tsuba-abcccc/maimai-queue-terminal/blob/v0.10.1/docs/public-beta-deployment.md)。

## 下载文件

- `maimai-Q-0.10.1-terminal-beta.apk`：连接自建服务端的现场终端版。没有预置地址或令牌，安装后由机厅管理员配置。
- `maimai-Q-0.10.1-local-beta.apk`：完全离线版，不申请联网权限，不提供网站或 Bot 同步。
- `public-site-0.10.1-beta.tar.gz`：独立公开队列页静态文件。
- `koishi-plugin-maimai-q-0.3.12.tgz`：Koishi 插件。
- `SHA256SUMS-0.10.1.txt`：发布附件校验值。

两个 APK 均使用既有 maimai Q 长期发布证书签名。证书 SHA-256 指纹：

```text
daa2e919d2f8d956c0a93417aae601e6ec658edc5ae7c9673830c53f649ec925
```

首次安装前必须核对附件 SHA-256。Debug 版和 Release 版签名不同，不能直接互相覆盖；已有 Debug 联调终端迁移前需要先保存数据并停止现场排队。

## 稳定支持范围

- 一个机厅对应一个独立 API 实例和 SQLite 数据卷。
- 同一队列只允许一台权威现场终端写入；备用终端只能在原终端离线后接管。
- Android 10 或更高版本。
- 服务端故障时现场终端仍能继续本地排队；网站、线上登记和 QQ Bot 会暂停。

多机厅必须使用相互隔离的 API、数据库、令牌和站点地址。多终端同时联动和正式多租户不属于本版本已经支持的能力。

## 更新方式

GitHub Releases 是唯一权威更新来源。本版本没有自动下载或自动安装；后续补丁会推进版本号并创建新的不可变 tag，不覆盖现有附件。更新前必须备份 SQLite、`.env`、反向代理、Bot、网站目录和 APK，按 API、网站、Bot、终端的顺序更新。

可以在 GitHub 使用“Watch → Custom → Releases”接收通知，或订阅：

```text
https://github.com/tsuba-abcccc/maimai-queue-terminal/releases.atom
```

## 已知边界

- 当前不提供预构建 Docker 镜像，API 由部署者从固定 tag 的 `cloud-server/` 构建。
- 版本信息只与服务端 `QUEUE_LATEST_*_VERSION` 配置比较，不会主动访问 GitHub。
- 网站不开放退出排队、暂缓一次、暂时离开、切换机台和修改偏好等高风险远程操作；这类操作继续由终端或已验证 QQ 的 Bot 完成。
- 测试版需要部署者自行承担现场联调、备份和恢复责任。
