# maimai Q 0.13.2 自定义头像与管理后台收尾

maimai Q 0.13.2 为已绑定网页账户的玩家增加自定义头像，并完成当前单终端架构下的管理后台设置能力。现场终端和本地版为 `0.13.2`（构建号 `68`），网站为 `0.13.2`，管理 App 使用独立版本 `0.13.1`（构建号 `67`），QQ Bot 保持 `0.3.13`。

> 本版本仍处于 `0.x` 测试阶段。升级服务端前必须备份 SQLite、环境文件、头像目录、API 文件和网站目录；真实现场覆盖安装前应确认 APK 使用既有长期发布证书。

## 自定义头像

- 只有已经绑定网页账户并登录的玩家可以修改头像。网页个人资料顶部居中显示头像，点击后调用系统图库或文件选择器。
- 浏览器和服务端均限制原图最大 8 MB；服务端通过 Pillow 解码，拒绝异常图片和过大像素尺寸，中心裁切为 512 × 512 WebP。
- 头像文件使用不可猜测的随机引用，不采用昵称、QQ、资料 UUID 或内容哈希作为公开文件名；响应使用一年不可变缓存。
- 终端只在玩家资料库原有头像组件中显示同步后的头像，不改变组件尺寸、间距、列表结构或其他队列 UI，也不提供终端上传入口。
- 头像加载失败、离线或遇到无效地址时，终端和网页继续显示昵称首字，不影响资料浏览和排队操作。

## 管理后台

- 手机竖屏管理 App 保留完整队列总览、线上登记立即签到、新建登记、任意登记编辑、顺序调整、玩家资料编辑和已绑定账户密码修改。
- 新增登记开放/关闭与清空确认、营业时间、机台分组、机台新增/删除、完整机台配置、机台停止/恢复，以及操作日志和来源筛选。
- 机台数量、容量和计划时间等风险设置仍必须先关闭登记；备注、分组和展示字段可按原有终端规则修改。服务端和现场终端都会复核配置修订、机台稳定身份和登记上下文。
- 正常拖动全队列排序是日常队列操作，不属于敏感设置，绑定管理后台后仍可使用。
- 同步总开关、同步模式、服务器地址和终端令牌尚未在管理 App 中提供完整的迁移与故障恢复语义，因此本版继续允许现场终端维护，不会因后台接管而锁死。

## 服务端升级

- SQLite 启动迁移会增加 `player_profile.avatar_reference`，不会清空现有资料。
- 安装新增的 Pillow 依赖，并设置持久化的 `QUEUE_PLAYER_AVATAR_DIRECTORY`。Docker 默认使用 `/app/data/player-avatars`；systemd 可使用 `/var/lib/maimai-queue-status/player-avatars`。
- Nginx 必须代理 `/api/player-avatars/`，并为精确路径 `/api/player-account/avatar` 设置至少 `9m` 的请求体上限；其他账户接口继续保持 `1m`。
- 生产环境将 `QUEUE_LATEST_TERMINAL_VERSION` 和 `QUEUE_LATEST_WEBSITE_VERSION` 更新为 `0.13.2`，Bot 最新版本保持 `0.3.13`。

- `maimai-Q-0.13.1-management.apk`：管理 App，不预置管理地址或令牌。
- `public-site-0.13.2-beta.tar.gz`：独立队列网站生产构建。
- `koishi-plugin-maimai-q-0.3.13.tgz`：配套 QQ Bot 插件。
- `SHA256SUMS-0.13.2.txt`：公开附件校验值。

预置现场地址或令牌的终端/管理测试 APK 仅供受控测试，不得进入公开 Release。

- Release APK 的 `zipalign`、`apksigner`、长期证书指纹、应用 ID、版本号、联网权限和敏感字符串检查。
- 生产部署后的健康、版本、未授权管理、未登录头像上传、不存在头像、网站 manifest、API/Bot/Nginx 服务状态核验。

当前环境没有确认可用的 Android 真机或模拟器，因此不把真实手机竖屏截图验收写成已完成；管理 App 已通过编译、单测和稳定尺寸约束审查。
