# maimai Q 0.13.0 管理后台（Android App）

## 目标

0.13.0 先交付一台手机竖屏使用的管理 App。它与现场终端、网页手机版共用队列状态文案和机台排版，面向机厅工作人员提供完整队列总览和受审计的管理命令。

## 已交付范围

- 管理 App 竖屏入口、服务地址和独立管理令牌配置。
- 完整队列总览：全部机台、当前游玩、等待位置、QQ、玩家资料关联、固定组合、暂缓、暂离和线上待签到。
- 线上登记立即签到。
- 管理后台新建正式登记。命令由服务端下发，现场终端和 `queue-core` 执行；不会直接写 `queue_snapshot`。
- 对任意关联玩家的登记执行暂缓一次、取消暂缓、暂时离开、取消暂时离开和退出排队。
- 访问玩家资料库，编辑昵称、性别、默认偏好、QQ 可见性、到访公开策略和终端编辑策略。
- 对已经绑定网页后台的玩家修改密码；修改后撤销该玩家现有网页会话。
- 审计来源增加“管理后台”，并保留命令回执、队列批次、机台稳定标识和机台配置修订校验。

## 权限边界

管理令牌不复用终端同步令牌或 QQ Bot 令牌，服务端拒绝未配置、过短或复用的令牌。管理命令必须经过服务端上下文校验，再由现场终端按 `queue-core` 规则最终执行。

正常拖动全队列排序是日常队列操作，不属于敏感权限策略。0.13.0 不改变现场终端现有拖动、`MoveWaitingPosition` 或 `ReplaceOrder` 行为，也不因管理后台绑定而关闭该能力。

玩家网页账户绑定后，网页账户当前仍按既有规则控制玩家资料的终端编辑状态；管理后台可以明确调整该资料策略。机厅级终端规则（例如全局同步和线上登记开关）的统一管理界面留待后续版本，不能把 0.13.0 的资料策略开关误解为所有机厅级设置已经开放。

## 暂不实现

- 在管理 App 中绑定或重新绑定网页后台。现阶段保留网页端原有绑定流程和管理后台的密码修改；没有账号的玩家不会由密码接口隐式创建账号。
- 用移动设备创建登记。管理 App 的新建登记使用独立 `CREATE_REGISTRATION` 管理命令，不开放或复用移动登记二维码入口。
- 多终端同时写入、多终端联动和主终端接替。本版本仍只有一台权威写入现场终端，但命令来源和回执字段为后续联动保留扩展位。

## 验证

- Android 管理 flavor：`compileManagementDebugKotlin`、`assembleManagementDebug`。
- Android 本地单元测试覆盖管理来源立即签到、新建登记、资料策略修改、命令解析和幂等回执。
- 服务端测试覆盖管理令牌、完整总览、立即签到、新建登记、任意玩家登记编辑、资料命令和密码重置。
- 现场终端玩家资料库在窄屏使用单列、较宽屏使用自适应多列；头像、昵称、默认偏好和玩家编号使用固定行高与间距，详情页保持同一身份块排版。
- 发布前必须分别检查无令牌 `401`、正确管理令牌 `200`、终端同步健康检查，以及正常拖动全队列排序仍可用。

## 后续管理能力

0.13.0 先交付管理后台的队列、玩家资料和已审计敏感策略能力。终端中尚未在管理后台提供的完整机台配置、业务时段、同步故障恢复、日志浏览和其他设置，列入后续管理版本；在这些入口实现前，不把它们标记为“已开放”。
