# 等待时间估算：新算法设计（草案，2026-11-25）

本文是等待时间估算的设计，维护者 2026-11-25 回复“按草案定”，正在实施。

文中的数字分三种：

- **已定**：维护者定的，标出原话；
- **由已定推出**：从维护者定的数字直接推出，写明怎样推出；
- **缺依据**：原来我暂时填的几个数，已由维护者提供，见第七节。

## 一、维护者的要求

维护者原话（2026-11-25），按提出的先后：

- “因某些玩家开启了自动安排，不确定他会不会被转出，因此导致队列时间不确定，原则上给各个登记提供的估时应该取小而不是取大，但这里我也不是说直接机械的取最小值，应该有算法”
- “创建登记之前‘新登记预计等待’那个并不遵循取小值，因为不设计个人时间安排”（按上下文理解为“不涉及个人时间安排”）
- “这个估计时间的算法你需要认真考虑一套新的，并且覆盖到各种场景，能够比较准确的提供给各个登记以及新加入的登记一个估计时间……如果不能给出一个准确的估计时间，对于单个登记的估计时间应该给出较小的结果，以便玩家妥善安排时间。”
- “30百分位数可以，但我觉得可以计算一下这个转出的置信率。比如，假设有人要转入，那么这个转入的置信率有多高的时候，这个估计时间就按转入后计算；假设有人要转出，这个可以一旦显示预览就按转出后更短的时间计算。”
- 先在现场收集一两周记录再切换：“没有这个条件。”
- “关于取整，如果不设计转入转出，至少30分钟内要精确到1分钟，30分钟以上100分钟以下精确到5分钟，100分钟以上精确到10分钟。”（“不设计”同样理解为“不涉及”）
- 涉及转入转出时的取整：“我没想好，你觉得怎样能兼顾，以准确为主，不要臆想数字写上去”
- “把可能不准确的情况单独写。如果转入置信率75以上就认为准确。可能不准确时，估计时间的文案要有变化。‘最快约xx分钟可以游玩’。你觉得呢？也可以写明‘由于涉及系统在两台机台之间的安排，时间估计可能不准确，请以现场实际情况为准’”

归纳为五条：

1. **已经登记的玩家**：结果不确定时，显示偏早的时间，让玩家提前回到现场。偏早的程度由算法决定，取第 30 百分位，不是取所有可能里最早的那个。
2. **加入之前的“新登记预计等待”**：只供玩家决定排哪台、要不要排，不涉及个人时间安排，所以不偏早，给居中的估计。
3. **转出和转入分开处理**：
   - 转出会让后面的人提前，预览一出现就按转出计算；
   - 转入会让后面的人推后，把握达到 75% 才按转入计算。
4. **可能不准确时单独显示**：文案改为“最快约 N 分钟后可以游玩”，并说明原因。
5. **没有现场数据可以先收集**，直接用计划时间切换。

## 二、现在的做法和问题

### 用到估时的地方

估时都在终端上算，随队列快照上传，网站、QQ Bot 和管理端显示的是同一组数字。

| 估时 | 显示在 |
| --- | --- |
| 每个等待位置多久后可以游玩 | 终端的位置菜单，网站的位置详情和“我的登记”，管理端的队列，QQ Bot 查询 |
| 新登记预计等待（每台机台一个） | 终端首页机台卡片，加入排队流程的左栏，网站，QQ Bot |
| 新登记是否会排到闭店之后 | 终端加入排队时的闭店提醒 |

没有按估时触发的通知。

### 现在的算法

- 按每台机台的计划时间（单人一轮默认 12 分钟，双人一轮默认 15 分钟，管理员可改）。
- 用真实的排队规则把之后的每一轮依次推演一遍。暂缓一次、暂时离开、固定组合、共同游玩的组合都按真实规则处理。
- 正在进行的一轮扣除已经玩过的时间；超出计划时间后，剩余时间算作 0。
- 待签到的线上登记一律算作会签到。
- 一对机台用另一套推算，把两台机台一起推演。
- 结果按分钟向上取整。

### 问题

1. **每轮时长是固定的**。现实中一轮有长有短，推演只给出“每轮都刚好按计划”这一种结果，无法知道这个结果有多不确定。
2. **自动安排的不确定没有算进去**。现在只有已经出现预览的登记，才会被算作转走或转来；已开启、但还没有出现预览的登记，一律算作留在原机台。
3. **待签到的线上登记一律算作会签到**。实际不签到的会被移除，后面的登记会提前。
4. **本轮超时后，剩余时间直接算作 0**。后面所有登记都按“下一轮马上开始”计算，这个口径没有依据。
5. **计划时间没有和实际对照过**。
6. 单台机台和一对机台是两套代码，各自维护，容易出现不一致。

## 三、新算法

### 思路：把未来推演很多遍

仍然用真实的排队规则一轮一轮地推演，但不只推一遍。每一遍里，凡是不确定的事情都各取一种可能，例如每一轮玩多久、待签到的登记会不会签到。每次推演 100 遍；100 遍只是计算量上的选择，实施时按平板的速度调整。

推演分两种：

- **自然推演**：两台机台一起推演，自动安排按真实的预览规则在每一遍里自行发生或不发生。它用来算两样东西：
  - 每份开启了自动安排的登记，转到另一机台的把握，即 100 遍里有几遍真的转过去；
  - 新登记预计等待。
- **偏早推演**：给已经登记的玩家估时。按下一节的规则先定下每一份可能转出、转入的登记算不算，然后对每台机台推演 100 遍，只剩每轮时长和签到这些不确定。每份登记得到 100 个结果，按从早到晚排好，取第 30 个，即第 30 百分位（已定）：100 遍里约有 30 遍会比显示的更早轮到。

这样，不确定越大，已登记玩家看到的时间就比中间值越早；几乎没有不确定时（例如前面只剩一轮），两者几乎相同。偏早多少由推演结果决定，不是固定地减去几分钟。

### 转出和转入怎样算

以机台 A 和机台 B 为一对，看机台 A 上的一份登记“甲”。

和甲有关的登记有三种：

- **转出**：排在甲前面、属于机台 A、开启了自动安排的登记，可能转至机台 B。它转走，甲就提前。
- **转入**：属于机台 B、开启了自动安排、按开始等待的先后在机台 A 的顺序里排在甲前面的登记，可能被安排到机台 A。它转来，甲就推后。
- **甲本人**：如果甲开启了自动安排，甲自己可能转至机台 B。

对每一份这样的登记，用自然推演算出它转过去的把握，按下表处理：

| 把握 | 判断 | 转出时 | 转入时 |
| --- | --- | --- | --- |
| 75% 及以上 | 准确：按会转计算 | 按转走计算 | 按转来计算 |
| 25% 及以下 | 准确：按不会转计算 | 按留下计算；但已显示预览的按转走计算，并显示为可能不准确 | 按不会转来计算 |
| 25% 至 75% 之间 | 可能不准确 | 按转走计算 | 按不会转来计算 |

说明：

- **75% 是已定的**（“如果转入置信率75以上就认为准确”）。
- **25% 由 75% 推出**：有 75% 的把握“不会转”，和有 75% 的把握“会转”同样算准确。否则另一机台上任何一份开启了自动安排的登记，哪怕几乎不可能转来，都会让后面的人显示“最快”。
- **两种情况取向相反，都偏早**：可能不准确时，转出按转走算，转入按不会转来算，所以甲看到的总是较早的那个时间，“最快”的说法才成立。
- **已显示预览的转出，按转走计算**，这是维护者说的规则。把握在 75% 以下时，甲的估时按“可能不准确”显示。
- **把握在 25% 至 75% 之间、还没显示预览的转出，我建议也按转走计算**。这是对维护者原来说法的补充，需要确认。否则它真的转走时，甲会比“最快”的时间还早轮到。
- **甲本人**：
  - 把握 75% 及以上，按机台 B 的时间计算；
  - 25% 及以下且没有预览，按机台 A 的时间计算；
  - 其余情况取两台中较早的时间，并按“可能不准确”显示。

只要以上任何一份有关的登记处在“可能不准确”一行，甲的估时就按“可能不准确”显示（见下一节）。排在甲后面的登记不影响甲，不计入。

同一份登记可能两边都按偏早处理：它在机台 B 显示了预览、把握却不到 75% 时，机台 A 的人按它转走计算，机台 B 的人按它不会转来计算。这是有意的，两边的人看到的都是较早的时间，并且都显示为“可能不准确”。

### 可能不准确时怎样显示

文案按维护者的意思写，用词按文案规范（这项功能写作“系统在……之间安排登记”，“系统”作主语）：

| 情况 | 估时文字 | 说明 |
| --- | --- | --- |
| 准确 | 约 N 分钟后可以游玩 | 不加 |
| 准确，且时间不到 1 分钟 | 预计很快可以游玩 | 不加 |
| 可能不准确 | 最快约 N 分钟后可以游玩 | 受系统在两台机台之间安排登记的影响，等待时间可能不准确，请以现场实际情况为准。 |
| 可能不准确，且时间不到 1 分钟 | 可能很快可以游玩 | 同上 |

- 维护者给的说明原句是“由于涉及系统在两台机台之间的安排，时间估计可能不准确，请以现场实际情况为准”。我改为上表中的写法，让功能名称与规范一致，主语落在“等待时间”上。
- 时间不到 1 分钟时，“最快很快”重复，改为“可能很快可以游玩”。
- 说明放在能写一句话的地方：
  - 终端的位置菜单；
  - 网站的位置详情和“我的登记”；
  - QQ Bot 的回复。
- 管理端的队列一行写不下说明，只把“预计 N 分钟”改为“最快 N 分钟”。
- 新登记预计等待是中间值，不是最早的时间，不用“最快”。加入排队流程左栏原有的说明“按当前队列估算，实际以轮到时为准。”已经足够。

### 取整

维护者定的取整方式（不涉及转入转出时）：30 分钟以内按 1 分钟，30 至 100 分钟按 5 分钟，100 分钟以上按 10 分钟。

我的建议：**涉及转入转出时，沿用同样的取整，不另设一套。**理由有两点：

- 可能不准确的部分已经由“最快”和说明交代清楚。数字本身仍是推演的结果，把它取得更粗并不会更准确。
- 另设一套更粗的取整，需要再定一组数字，而这组数字没有依据。

取整的方向：

| 估时 | 方向 | 理由 |
| --- | --- | --- |
| 准确 | 四舍五入 | 第 30 百分位已经偏早，取整不再额外偏早 |
| 可能不准确（“最快”） | 向下取整 | 保证显示的确实不晚于推演得出的最早时间 |
| 新登记预计等待 | 四舍五入 | 居中的估计 |

### 每一遍怎样推演

1. **每轮时长**：按机台、单人或双人分别抽取。
   - 范围是计划时间少 2 分钟到多 3 分钟（已定：“单人10-15分钟，双人13-18分钟，也就是向下浮动两分钟，向上浮动三分钟”）。管理员改了计划时间，范围随之移动。
   - 范围内以计划时间最常见，越靠近两端越少（三角形分布）。这只用到维护者给的三个数：最短、计划、最长。
   - 同一遍里每一轮各自抽取。
2. **正在进行的一轮**：只从“比已经玩过的时间更长”的那部分里抽取，算出还剩多久，不再直接算作 0。
   - 超出计划时间以后，剩余时间在“到计划时间加 3 分钟为止”的范围里取（由上一条推出）。
   - 已经超过计划时间加 3 分钟的，按马上结束计算。
3. **换人的时间**：计划时间视为包含换人，不单独计算。
4. **自动安排**：
   - 自然推演中，按真实的预览规则推演：预览出现的门槛 3 分钟、中断的门槛 1 分钟，连续显示满 12 分钟才安排，本轮超过 20 分钟时暂停计时。这些都是现有规则。
   - 偏早推演中，按上面的表事先定下算不算，不再在推演中变化。
5. **待签到的线上登记**：按五成会按时签到抽取（已定：“五成线上登记按时签到”）。没有签到的，轮到时按规则移除。
6. **暂缓一次、暂时离开**：按现有规则处理。
   - 暂缓的登记跳过下一次机会。
   - 暂时离开的登记不参与组合、不挡后面的人，轮空 3 次后移除。
   - 暂时离开的玩家何时回来无法预测，其本人仍显示“暂时离开，无法估算”。
7. **未到场、主动退出、人工调整顺序**：从队列里看不出来，不做预测，由“偏早”的原则兜底；发生之后立即重新推演。
8. **新加入的登记**：不影响已有登记的估时，推演时不加入。原因有两点：
   - 新登记排在队尾；
   - 自动安排也不会把后来开始等待的登记排到先开始等待的登记前面。

### 让数字稳定

- **每一遍用的随机数事先固定**（按机台和轮次编号决定）。终端每 30 秒重算一次，但数字只在队列真正变化或时间推移时才变，不会忽大忽小。
- **同一台机台上，后面位置的估时不小于前面位置**。按等待顺序逐个取不减的值；同一位置里的两份登记时间相同。

### 各种情况怎样处理

| 情况 | 处理 | 显示 |
| --- | --- | --- |
| 单台机台，单人或双人 | 每一遍按抽取的时长推演 | 准确 |
| 本轮未超出计划时间 | 剩余时间从“比已玩时间更长”的部分抽取 | 准确 |
| 本轮已超出计划时间 | 剩余时间在到计划时间加 3 分钟为止的范围里抽取；超过的按马上结束 | 准确 |
| 游玩位置空着，但有人等待 | 按现有口径，视为下一轮马上开始 | 准确 |
| 有登记暂缓一次 | 按规则跳过一次 | 准确 |
| 有登记暂时离开 | 不挡人；本人不估时 | 本人：暂时离开，无法估算 |
| 有待签到的线上登记 | 按比例抽取是否签到 | 准确 |
| 固定组合、共同游玩、只容纳一人的机台 | 按真实规则 | 准确 |
| 前面有转出，把握 75% 及以上 | 按转走计算 | 准确 |
| 前面有转出，把握 25% 至 75% | 按转走计算 | 最快 |
| 前面有已显示预览的转出，把握 25% 及以下 | 按转走计算 | 最快 |
| 前面有转入，把握 75% 及以上 | 按转来计算 | 准确 |
| 前面有转入，把握 25% 至 75% | 按不会转来计算 | 最快 |
| 前面的转出、转入把握都在 25% 及以下，且没有预览 | 按不转计算 | 准确 |
| 开启自动安排的登记本人 | 见上一节 | 视把握而定 |
| 一台机台本轮超过 20 分钟 | 自然推演里同样暂停安排 | 视把握而定 |
| 当前机台停止使用 | 当前机台的登记不估时；开启自动安排的登记按另一机台推演 | 视把握而定 |
| 另一机台停止使用 | 不会转去，也不会转来 | 准确 |
| 登记已满 | 新登记预计等待显示“登记已满” | 不变 |
| 临近闭店 | 加入前的闭店提醒用新登记预计等待（中间值） | 不变 |
| 有人未到场、退出，或顺序被调整 | 不预测，发生后重新推演 | 之后的数字随之变化 |

### 新登记预计等待

- 在这台机台的队尾假设一份新登记：允许他人加入（只容纳一人的机台为单人），不开启自动安排。
- 用自然推演，取中间值，不偏早，不用“最快”。
- 一对机台的机台，仍是这台机台自己的时间，不在两台之间取较小值；别人的转出和转入，按自然推演里实际发生的情况计入。
- 闭店提醒也用这个值。

## 四、实测记录（以后再做，不影响切换）

维护者说明现在没有先在现场收集记录的条件，所以直接用计划时间切换。下面三类记录可以以后再加，用实测数据检验或替换维护者给出的范围和签到比例。都只存在终端本机，不含玩家信息：

1. **轮次记录**：每结束一轮，记下以下内容：
   - 机台、单人还是双人；
   - 开始和结束的时刻；
   - 结束方式：正常结束本轮，或是撤回、人工调整等。
2. **签到记录**：线上登记轮到时是否已经签到。
3. **估时回看**：每份登记进入游玩位置时，记下两组数字：
   - 它加入时和开始前 30、15 分钟时显示的估时；
   - 实际等了多久。

有了估时回看，就能检查两件事：

- “约三成会比显示的更早轮到”是否做到；
- 标为准确的估时，是否真的比标为“最快”的更接近实际。

## 五、计算量和实现方式

- **自然推演**：每一遍与现在一次一对机台的推算相当，100 遍约为现在的 100 倍。推演里判断“另一机台能否更早安排”本身也是一次推算；若逐遍完整嵌套太慢，改用简化的判断，实施时用测试确认简化前后结果相近。
- **偏早推演**：转出转入已事先定下，每台机台单独推演，计算量小得多。
- **刷新**：终端每 30 秒和每次队列变化后重算，放在后台计算，算完再更新画面；上传网站的快照用同一份结果，并带上“可能不准确”的标记。
- **测耗时**：实施前先在平板上测，不够快时减少遍数。
- **合并代码**：单台机台和一对机台合并为同一套推演；终端、管理端、网站、Bot 显示同一组结果。
- **规则不变**：预览和自动安排的规则不变，它们仍按现在的推算决定谁在什么时候被安排。新算法只改变显示给玩家的估时，不影响登记转至哪台机台。
