# maimai Q 0.13.3 网页登录与二维码建档

maimai Q 0.13.3 收尾网页玩家登录和玩家资料创建流程。现场终端与本地版为 `0.13.3`（构建号 `69`），网站和服务端最新版本为 `0.13.3`，管理 App 继续使用独立版本 `0.13.1`（构建号 `67`），QQ Bot 保持 `0.3.13`。

> 本版本仍处于 `0.x` 测试阶段。升级服务端前必须备份 SQLite、环境文件、API 文件、网站目录和头像目录；真实现场覆盖安装前应确认 APK 使用既有长期发布证书。

## 网页分步登录

- 登录弹窗初始只显示 QQ 输入框和“继续”。
- 服务端查询只返回 `bound: true/false`，不返回昵称、资料 ID、玩家编号、机厅或账户信息。
- 已绑定时才显示密码输入框、“忘记密码？”和登录按钮；忘记密码继续由现场管理员完成身份核验和密码处理，网页端不提供仅凭 QQ 的自助重置。
- 未绑定时明确提示先在现场终端打开玩家资料并绑定网页账户；玩家可以更换 QQ 重新查询。
- 查询使用独立请求限流，不会消耗密码登录失败额度。

## 二维码创建网页玩家资料

- 终端点击“新建玩家资料”时默认向当前同步服务创建一次性二维码；手机页面优先适配竖屏，填写昵称、性别、QQ、默认游玩偏好、通知选项和密码。
- 提交在一个数据库事务中创建玩家资料、六位玩家编号、网页账户和当前资料索引，并自动登录新账户。
- 新资料默认 `web_account_bound=1`、`terminal_editing_allowed=0`、QQ 展示范围为网站公开；玩家可以在网页设置中重新开放终端编辑。
- 终端仍保留“仅创建本地玩家资料”。这条路径仍把资料上传到云端资料库，但不绑定网页账户，因此不提供网页登录密码。
- 创建会话绑定物理终端的运行实例 ID 和代次。同一实例重复请求保持幂等；终端重启、实例变化、过期或完成后，旧二维码会安全失效。
- 终端尚未把新资料回显到下一份快照时，服务端的待同步索引会暂时保留该资料，避免上传旧快照删除刚创建的资料。

## 队列和权限边界

- 普通全队列拖动和等待顺序调整是日常队列操作，不属于敏感设置；绑定管理后台不会禁用它。:codex-annotation{index="1"}
- 管理后台继续以现场终端和 `queue-core` 的能力为基准，不以 QQ Bot 或网页端的能力子集为基准。
- 多终端同时写入、权威终端接管和冲突仲裁不在本版本，安排在 `0.14.0` 设计和实现。

## 服务端配置迁移

新增可选环境变量：

```dotenv
QUEUE_PLAYER_PROFILE_CREATION_TTL_SECONDS=600
QUEUE_PLAYER_PROFILE_CREATION_SESSION_RETENTION_SECONDS=86400
QUEUE_PLAYER_AUTH_LOOKUP_LIMIT_REQUESTS=30
```

旧的 `QUEUE_PLAYER_PROFILE_CREATION_RETENTION_SECONDS` 仍作为兼容回退名称读取。SQLite 启动时会创建 `player_profile_creation_session` 和 `pending_player_profile_sync` 表，并为已有创建会话补齐运行实例字段，不会清空玩家资料或队列。

公开部署还必须将 `/api/player-profile-creation/` 代理到 API。终端只通过受保护的 `/api/queue-terminal/player-profile-sessions` 创建会话，手机网页使用二维码中的一次性令牌访问 `/api/player-profile-creation/sessions/<token>` 和 `/complete`；不能把终端同步令牌写入网页构建配置。

## 验证范围

- 服务端 `python -m py_compile app.py` 和完整单元测试。
- 网页 Vite 生产构建、分步登录、二维码页面及移动端窄屏样式审查。
- Android local、terminal、management flavor 编译和 Release APK 元数据、签名、联网权限、竖屏约束与敏感值扫描。
- 生产部署后的健康、版本、数据库完整性、网站 manifest、未授权接口和队列连续性检查。

当前开发机没有可用的 Android 真机或模拟器，因此真实触控、扫码和竖屏截图验收必须由现场测试继续完成；这不影响源码和构建门槛测试结论。
