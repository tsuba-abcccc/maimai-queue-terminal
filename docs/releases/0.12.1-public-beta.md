# maimai Q 0.12.1 公开测试版

maimai Q 0.12.1 完成网页玩家资料与本人登记管理的首轮问题修复，并补齐账户解绑、迁移和冲突边界。部署者仍可使用自己的服务器、域名、数据库、网站和 QQ Bot，不依赖项目维护者服务器。

> 本版本仍处于 `0.x` 测试阶段。真实现场更新前应先备份终端数据和服务端 SQLite，并完成网站、Bot、终端与移动设备登记的联调。

## 本次更新

- 玩家资料可以在现场终端生成一次性二维码，绑定网页玩家资料。玩家使用 QQ 和密码登录后，可管理昵称、性别、默认游玩偏好、通知、公开范围、终端编辑权限、QQ 和密码。
- 网站登录后会自动识别本人登记。点击自己的登记或队列位置仍显示完整机台、位置、估时、偏好和状态详情，并可执行暂缓一次、暂时离开、取消对应状态、转至其他机台、修改本次偏好和退出排队。
- 网站远程操作采用与终端一致的确认说明，并锁定确认时的队列批次、登记、机台、固定组合、暂缓或暂离状态、轮空次数及签到状态。终端离线、机台停止使用或未开启网站远程操作时，会显示具体原因而不是提交无效命令。
- 待签到线上登记在网页只允许退出排队；签到仍必须在现场终端完成。线上登记的 30 分钟签到时限和轮到时自动退出规则没有改变。
- 新建玩家资料的 QQ 显示范围默认允许网站公开；升级前已有资料和玩家已经选择的范围保持不变。
- 已绑定资料不再允许从公共终端重新绑定或重置密码。资料被解除绑定、迁移、合并或发生 QQ 归属冲突时，旧账户、登录会话和未使用绑定页面会一并失效，避免残留凭据继续访问或阻塞重新绑定。
- Bot 查询本人登记时以玩家资料中的最新 QQ 为准。玩家在网页修改 QQ 后，旧 QQ 不再匹配登记，新 QQ 可以继续使用 Bot。
- 机厅营业时间随服务端同步，终端、网站和 Bot 使用同一营业状态。现有闭店收尾、正常轮换、暂缓一次、暂时离开、固定组合、共同游玩预览、待签到投影和估时规则均未改变。

## 下载文件

- `maimai-Q-0.12.1-terminal-beta.apk`：连接自建服务端的现场终端版。没有预置服务端地址或令牌，安装后由机厅管理员配置。
- `maimai-Q-0.12.1-local-beta.apk`：完全离线版，不申请联网权限，不提供网站或 Bot 同步。
- `public-site-0.12.1-beta.tar.gz`：独立公开队列页与网页玩家资料的静态文件。
- `koishi-plugin-maimai-q-0.3.13.tgz`：本版本配套的 Koishi 插件。
- `SHA256SUMS-0.12.1.txt`：全部发布附件的 SHA-256 校验值。

两个 APK 均使用既有 maimai Q 长期发布证书签名。证书 SHA-256 指纹：

```text
daa2e919d2f8d956c0a93417aae601e6ec658edc5ae7c9673830c53f649ec925
```

Release APK 与 Debug 联调包签名不同，不能直接互相覆盖。已经安装 0.10.1 或 0.11.0 公开测试 Release 的设备可以保留数据覆盖升级；从 Debug 包迁移前应先保存数据并停止现场排队。

## 部署与更新

服务端、网站、Bot 和终端必须使用同一 Release。推荐更新顺序为服务端、网站、Bot、终端；每一步完成后再检查 `/queue-api-healthz`、网站版本详情、Bot 查询和终端同步。

服务端从固定 Tag 的 `cloud-server/` 构建，网站直接解压静态附件，Bot 直接安装 `.tgz`。完整步骤见[公开测试版自建部署方案](../public-beta-deployment.md)。更新前必须备份 SQLite、`.env`、反向代理配置、Bot 配置、网站目录和终端数据。

## 验证范围

- 服务端 144 项测试、Koishi Bot 80 项测试、Android 应用与队列核心单元测试全部通过。
- 独立公开网站和复用队列组件的网站构建通过，共享组件一致性检查通过。
- 浏览器行为测试覆盖网页登录后打开本人登记、提交退出排队，以及待签到登记关闭再打开后的状态恢复。
- Release APK 已核对版本号、应用 ID、联网权限、非 Debug 标记、长期签名证书，以及空的内置服务端地址和令牌。

## 已知边界

- 一个服务端实例仍只支持一个活动机厅和一台权威写入终端；多机厅与多终端同时联动尚未开放。
- 忘记网页密码时不允许在公共终端直接重置，当前需由管理员线下核验处理。
- 网站只能管理当前登录资料对应的本人登记，不能远程签到、结束本轮、调整他人登记、拖动顺序或修改终端设置。
- 当前不提供预构建 Docker 镜像，API 仍由部署者从固定 Tag 构建。
