# maimai Q 开发与交付记录

本文件长期保留已经完成工作的实现决策、风险判断、验证结果和遗留事项。记录采用只追加方式维护：既有条目不因任务结束而清空；需要纠正时新增说明，不覆盖原始结论。

本文件记录可审阅、可复核的工程依据，不记录模型内部隐藏推理过程。正式对外发布内容仍以版本更新日志和 GitHub Release 为准。

## 2026-08-11 · 0.10.0 部署收尾与查询人数

### 已完成

- 云端后端已支持同步协议 schema 7，并完成真实数据库迁移。健康检查会校验关键迁移是否就绪，数据库结构不完整时返回 HTTP 503。
- 网站已支持 1 至 10 台机台、机台分组和移动设备登记快捷确认，并推送至 `site-docs/main`、部署到生产站点。
- 移动设备登记只在现场终端最终确认成功后记住稳定玩家资料 ID。下次扫码先校验会话和资料，再直接进入“确认本次登记”；仍可返回资料库改选，失效或已合并的资料记忆会自动清理或迁移。
- Koishi 插件 `0.3.11` 已部署。主菜单在“查看队列”后显示“查询人数”；命令动态统计 A 至 J 的全部机台，并根据终端离线、停止使用、关闭登记和测试数据状态调整说明。
- 终端中的“网站同步”已统一更名为“与服务端同步”，底层兼容字段未修改。

### 关键决策

- 协议升级按“后端先兼容、再更新客户端”的顺序部署。不能仅以 systemd 进程存活判断成功，必须同时验证数据库迁移、公开接口、私有接口和真实终端上传。
- “查询人数”只读取公开队列快照，不读取个人资料，因此可以在群聊和私聊使用。统计不写死两台或四台机台，避免后续 A 至 J 配置再次产生行为偏差。
- 浏览器记住玩家时不保存昵称、QQ 或登记编号，只保存稳定资料 ID。昵称变化、退出后重新登记或队列批次变化不会把记忆指向其他玩家。
- 网站发布继续使用 `dist-next` 验证后原子切换，失败时保留上一份 `dist-previous`，避免玩家访问到半套资源。
- Koishi 更新前同时备份依赖声明、锁文件、旧安装包和已安装插件目录；安装包校验一致后才停止服务并切换版本。

### 验证结果

- 后端测试 94 项通过，关键公开及私有接口返回 200，数据库完整性检查为 `ok`。
- Android 单元测试与 `lintTerminalDebug` 通过；当前测试终端曾使用 App `0.10.0`、schema 7 成功同步。
- Koishi 测试 68 项通过；生产服务加载插件 `0.3.11`，OneBot WebSocket `127.0.0.1:3001` 为已连接状态，`get_login_info` 返回成功。
- 生产队列快照已使用 `0.3.11` 的实际格式化代码验证“查询人数”，可完整列出当前 A、B、C 三台机台。
- 网站构建和真实浏览器行为测试通过，覆盖记住玩家后直达确认页、返回改选玩家、失效记忆清除、手机视口及多机台布局；生产 `/queue-status` 返回 HTTP 200。

### Koishi 控制台访问决策

- 生产 Koishi 控制台继续只监听服务器 `127.0.0.1:5140`，不直接开放公网端口。
- 临时访问使用 SSH 本地端口转发。需要从同一局域网的其他设备访问时，转发只绑定操作电脑的局域网地址，并把 Windows 防火墙规则限制在本地子网；关闭 SSH 进程后入口立即失效。
- 当前控制台认证插件未启用，因此不应把 5140 端口长期开放到公网或不受信任网络。
