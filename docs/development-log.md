## 2026-08-18 至 2026-08-19 · 0.12.1 账户边界与网页操作审查

### 本轮实现与审查结论

- 网页登录玩家点击自己的登记或队列位置时，继续保留队列详情、位置、估时、机台状态和本次游玩信息，再打开与现场终端一致的操作菜单；退出排队、暂缓一次、暂时离开、转至其他机台和本次游玩偏好修改均提交给现场终端最终校验。
- 网页操作在终端离线、机台停止使用或未开启网站远程操作时仍可打开查看，但会显示对应原因并阻止提交；待签到线上登记只显示退出排队。固定组合、容量为 1 的机台、暂缓一次和暂时离开的提示按实际受影响的登记分别说明。
- 账户绑定入口改为一次性绑定：已绑定资料不再显示公共终端重新绑定入口，旧绑定页面不能重置密码。资料从服务端导入为未绑定状态时，旧账户、会话和未消费绑定凭据会失效，之后可以重新绑定。
- 处理 QQ 归属冲突和历史资料合并时，同步清理旧资料的网页账户和登录会话，避免出现“QQ 已清空但账户仍占用、既不能登录也不能重新绑定”的孤立状态。绑定入口也会先清理未绑定资料遗留的孤立账户，防止旧账户主键阻塞重新绑定。账户查询、登录和绑定页面额外核对 `web_account_bound`，旧会话不能绕过资料绑定状态。
- 公开站点 `public-site/` 与 `D:\site-main` 的五个共享组件已同步；两个站点分别构建，不覆盖其他站点内容。

### 验证结果

- 服务端 `144` 项测试通过，包含旧账户会话失效、孤立账户重新绑定、QQ 冲突清理、网页登录玩家本人登记退出排队和线上登记待处理状态恢复。
- Koishi Bot `80` 项测试通过；Android/队列核心 `:app:test` 与 `:queue-core:test` 通过；公开站点 Vite 构建和 `site-main` VitePress 构建通过。
- `git diff --check` 通过。`output/apk/maimai-Q-0.12.1-local.apk` 与 `maimai-Q-0.12.1-terminal.apk` 是 Debug 联调包；公开附件由同一源码重新构建为非 Debug Release，并使用既有长期发布证书签名。联网 Release 的内置服务端地址和令牌均为空，可以由部署者安装后自行配置。

### 未改变的核心规则

- 闭店收尾、登记排队开关、正常轮换、暂缓一次、暂时离开、待签到 30 分钟及轮到时移除、固定组合、共同游玩预览、游玩位置和估时规则均未改变。

## 2026-08-12 · 0.10.2 同步故障修复与公开测试发布

### 实现决策

- 终端重启恢复旧日志时，必须区分 JSON `null` 与文字 `"null"`。历史系统事件和玩家资料事件不应携带机台身份；载入迁移和上传规范化各自独立执行，避免单一修复点遗漏内存中已有的坏数据。
- 服务端只兼容已知旧版本产生的 `machine_name="null"` 且没有有效机台 ID 的系统事件。其他错误机台字段继续按非法快照拒绝，不能通过宽松清洗掩盖新客户端缺陷。
- 同步错误采用稳定错误代码和精确字段路径，并附事件序号、标题和登记编号；现场不再只看到无法对应根因的通用校验错误。
- 关闭同步、测试终端恢复、命令领取，以及网站与移动设备同时登记同一玩家，都在最终写入事务内复核权威状态，避免只依赖请求开始时的旧快照。
- 0.10.1 尚未形成不可变公开 Release，因此本轮不覆盖或伪造旧 Release，直接推进至 `0.10.2`；公开 APK 继续使用既有长期证书，联网终端包显式禁止嵌入任何私人服务器地址或令牌。

### 行为边界

- 本轮没有修改闭店收尾、登记开放、正常轮换、暂缓一次、暂时离开、待签到、固定组合、共同游玩预览或撤销规则。
- 服务端先兼容旧终端，再更新终端。部署必须在前后核对生产队列 ID、修订号和数据库完整性；失败时同时回滚代码和数据库。
- 网站共享组件仍以 `public-site/` 为规范源，发布时同步到各独立站点，分别构建、部署和提交，避免独立站点停留在旧前端。

### 验证基线

- 修复提交前 Android 与队列核心共 445 项、服务端 125 项测试通过，`git diff --check` 通过。
- 正式发布还必须完成相同证书指纹校验、APK 包内私人配置扫描、公开网站构建、生产健康检查、版本接口和 GitHub 附件 SHA-256 核验；完成结果在发布后追加记录。

### 发布验证结果

- Android 与队列核心 local/terminal 测试、两个 Release 变体 Lint 和构建通过；服务端 125 项、Koishi 80 项测试通过，公开站点与其他独立站点均完成生产构建。
- 两个 APK 的版本为 `0.10.2`、构建号为 `60`，证书 SHA-256 与 0.10.1 长期证书一致。联网终端包的构建配置中服务器地址和同步令牌均为空，未发现维护者域名；本地版不申请联网权限。

### 关键决策

- 协议升级按“后端先兼容、再更新客户端”的顺序部署。不能仅以 systemd 进程存活判断成功，必须同时验证数据库迁移、公开接口、私有接口和真实终端上传。
- “查询人数”只读取公开队列快照，不读取个人资料，因此可以在群聊和私聊使用。统计不写死两台或四台机台，避免后续 A 至 J 配置再次产生行为偏差。
- 浏览器记住玩家时不保存昵称、QQ 或登记编号，只保存稳定资料 ID。昵称变化、退出后重新登记或队列批次变化不会把记忆指向其他玩家。
- 网站发布继续使用 `dist-next` 验证后原子切换，失败时保留上一份 `dist-previous`，避免玩家访问到半套资源。
- Koishi 更新前同时备份依赖声明、锁文件、旧安装包和已安装插件目录；安装包校验一致后才停止服务并切换版本。

### Koishi 控制台访问决策

- 生产 Koishi 控制台继续只监听服务器 `127.0.0.1:5140`，不直接开放公网端口。
- 临时访问使用 SSH 本地端口转发。需要从同一局域网的其他设备访问时，转发只绑定操作电脑的局域网地址，并把 Windows 防火墙规则限制在本地子网；关闭 SSH 进程后入口立即失效。
- 当前控制台认证插件未启用，因此不应把 5140 端口长期开放到公网或不受信任网络。
