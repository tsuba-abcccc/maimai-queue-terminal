# maimai Q 文案规范

本文规定 maimai Q 各部分界面文字的写法。新增或修改文案时按本文执行；本文没有写到的情况，先查现有文案里同类句子的写法，照着写。界面的颜色、字号、按钮样式等见[界面规范](ui-guide.md)。

每条规则后面标了来源：**已定**表示维护者明确决定；**现状**表示现有文案几乎全部如此，本文只是把它固定下来。

## 适用范围

- 现场终端、管理后台、网页端的全部界面文字。
- 服务端返回给人看的提示（接口响应里的 `error` 和命令结果里的说明）。
- 写入日志并展示的标题和内容。
- QQ Bot 的回复。当前的 Bot 计划换框架重写，在此之前只跟随用词表，不逐句调整。

不适用于：应用内的历史版本说明（属于记录，不回头改）、`docs/` 下的文档、代码里的英文标识符。

## 语气

1. 用书面陈述句说明事实和结果。（现状）
2. 不称呼对方，不写“你”“您”“你们”；需要指明主体时写“本人”“这份登记”“这名玩家”。（已定）
3. 不用口语连接词和语气词，例如“所以”“但是”“的话”“就”“哦”“吧”。（现状）
4. 不写安慰、寒暄或劝告性的句子；需要对方操作时，用“请……”直接说明要做什么。（现状）
5. 不用感叹号。（现状）

| 缩短等待时间 | 缩短排队等待 | | 已定 |

| 当前 | 目前 | | 现状 |

| 管理员 | 现场工作人员、现场管理员 | 只有管理后台能做的事（重置网页密码、开启 QQ Bot 联动、处理重复资料）找“管理员”。排队操作是现场玩家自己点的，不写“工作人员” | 已定（2026-11-24） |
| 退出排队 | 离队、离开队列 | 只用于玩家自己决定离开 | 已定（2026-11-24） |
| 撤回至等待顺序 | 撤回至队首 | 把游玩位置上的登记撤回等待顺序（撤回后在队首）。游玩位置不属于等待顺序，所以操作名不写“队首” | 已定（2026-11-24） |
| 移除登记；系统按规则拿掉时写“自动移除” | 退出队列、删除登记、出队；系统拿掉时写“自动退出排队” | 由别人决定时用：现场其他人（通常是其他玩家）或管理后台拿掉登记写“移除登记”，系统按规则拿掉（线上登记超时未签到、轮到时未签到、暂时离开第 4 次轮到）写“自动移除” | 已定（2026-11-24） |
| 修改（昵称、玩家资料、密码、设置） | 更改 | 两个词各有固定的对象，一一对应，不混用；不需要只留一个（2026-11-23 定） | 已定 |
| 更改游玩偏好、更改本次游玩偏好、游玩偏好已更改 | 修改游玩偏好 | 操作名和句子里都用“更改”。Bot 保留“修改游玩偏好”作为玩家仍可输入的别名，但不再显示 | 已定（2026-11-23） |

以下各组不是同义词，不要合并：

| 词 | 含义 |
| --- | --- |
| 朋友 / 好友 | 朋友指固定组合里的另一名玩家；好友只指 QQ 好友 |
| 服务端 / 服务器 | 服务端指同步的对象（“与服务端同步”）；服务器指地址和连接（“服务器地址”） |
| 网页端 / 网页账户 | 网页端指玩家使用的公开页面（队列页、账户、手机扫码登记页）；网页账户是玩家登录用的账户。不写“网站”（维护者 2026-11-28：“全改成网页端吧”；此前一度统一为“网站”） |
| 由管理后台接管的设置 | 管理后台可以接管的那几项终端设置（是否允许线上登记、暂缓一次、暂时离开、QQ Bot 联动）。不写“终端敏感策略”“终端接管策略”这类自造简称，把意思说全（维护者 2026-11-28） |
| 稍候 / 稍后 | 请稍候是请等待；稍后是过一段时间 |
| 已过期 / 已失效 | 数据和二维码过期；登录状态和会话失效 |
| 撤销 / 撤回 | 撤销是撤销一次操作；撤回是把登记撤回等待顺序 |
| 取消 / 解除 | 取消暂缓一次、取消轮空一次、取消暂时离开；解除固定组合；暂缓一次跳过后“自动解除暂缓”，轮空一次移至队尾后“随即自动解除” |
| 编辑 / 修改 | 编辑是打开编辑页面的入口和页面标题（编辑玩家资料、编辑登记、编辑机台）；修改是改动本身和结果（修改昵称、玩家资料已修改）。设置名“允许现场终端编辑资料”保留 |

其他约定：

- 机台写作“机台 A”，前面可以带备注，例如“入口侧·机台 A”。数机台用“台”：两台机台。（现状）
- 中点“·”两侧不写空格；终端显示时会自动在两侧留出略窄于半角空格的空白，见界面规范“字号”一节。（已定，2026-11-24）
- 正文里提到按钮时写“点击‘按钮名’”，例如“点击‘保存设置’后统一生效”。（现状）
- 分步填写的按钮：中间各步写“下一步”；从摘要进入某一步时写“完成修改”；最后一步写“完成创建”，编辑时写“保存玩家资料”。分步页面的标题用动宾短语，例如“填写 QQ 号”“设置排队通知”“确认玩家资料”。（已定，2026-11-24）
- 功能名不加引号，例如暂缓一次、固定组合、共同游玩预览。只有“使用”后面的选项值加引号：本次将使用“单人游玩”。（现状）
- 不为简单的概念另起名字，也不用自造的简称；能字对字读懂的写法优先。句子不好断时改句子，不靠引号。（已定）
- 玩家资料与登记的关系：登记是玩家资料的载体，一份登记由一份玩家资料创建，也可以是没有资料的临时登记。写“使用这份资料创建登记”。（已定）

### 自动在两台机台之间安排登记（2026-11-23 定稿）

这项功能没有名称。它是单份登记的本次游玩偏好里的一个勾选框，玩家资料里没有对应的设置。对玩家和工作人员的文字一律不说“同时在两台机台排队”：登记只在一台机台排队，可以由系统安排到另一台。

| 概念 | 用词 | 不再使用 |
| --- | --- | --- |
| 称呼这项功能（标题、章节名，或句子里需要点名时） | 自动在两台机台之间安排登记 | 同时在两台机台排队、同时排队、双机排队 |
| 描述内容（前面有“允许”“已允许”，或句子需要说明由谁来安排时） | 系统在……之间安排登记，“系统”作“安排”的主语。例如：允许系统在当前机台和 机台 B 之间安排登记 | 允许自动在……之间安排登记 |
| 短写 | 不设。位置紧张时只可以省去“登记”：已允许系统在两台机台之间安排。前面有“允许”“已允许”时“系统”不能省 | 系统安排、自动安排（后者在现有文字里指自动选出下一组，例如“不会自动安排下一组”）、允许在两台机台之间安排 |
| 规则不允许时 | “系统规则不允许”后面接功能的名称，与“系统规则不允许暂缓一次”同一句式：系统规则不允许自动在两台机台之间安排登记 | 系统规则不允许系统…… |
| 登记怎样移动 | 自动转至。“自动”只作“转至”的状语，说明不需要人操作 | 系统转至、由系统自动转至、系统自动安排 |
| 玩家的选择 | 允许；状态写“已允许” | 接受、同意 |
| 勾选框的动作 | 开启 / 取消 | 勾选、取消勾选、关闭 |
| 句子里指这个勾选框 | 这项选择 | 这项功能 |
| 登记所在的机台 | 当前机台 | 此机台、本机台、这台机台 |
| 另一台 | 另一机台；需要点名时写机台名；同一句里第二次提到用“其” | 对方机台、配对机台 |
| 登记的移动 | 转至。后面必须有宾语：转至 机台 B、转至另一机台（2026-11-24 定） | 切换、转移、调整；单说“手动转至”“不转至” |
| 机厅设置里的两台 | 一对机台 | 同时排队的一对机台 |
| 系统判断哪台更快 | 能够更早安排（这份登记）游玩 | 先轮到、先空出 |
| 有前提 | 符合条件时 | |
| 生效和恢复的时间 | 游玩一轮之后 / 游玩一轮之前 | 本轮、下一轮（用在等待中的登记上；“本轮”只指游玩位置上正在进行的那一轮） |
| 这一轮不安排 | 不会被安排到另一机台 | 不再保留位置、放弃位置 |
| 灰色条目 | 预览 | |

- 同时提到两台机台时，登记所在的机台在前，另一机台在后。
- 协议文档描述内部做法时可以说“在另一机台取得位置”，那不是给玩家看的文字。

### 等待时间（2026-11-25 定）

| 情况 | 写法 |
| --- | --- |
| 已登记，估时准确 | 约 N 分钟后可以游玩；不到 1 分钟时写“预计很快可以游玩” |
| 已登记，可能不准确（涉及两台机台之间的安排） | 最快约 N 分钟后可以游玩；不到 1 分钟时写“可能很快可以游玩”，不写“最快很快” |
| 同上，且“最快”与“系统未安排时”相差 24 分钟以上（2026-11-28 定） | 第一行照旧：最快约 N 分钟后可以游玩（不到 1 分钟时写“可能很快可以游玩”）。下面另起一行写明另一个时间及其条件：系统未在两台机台之间安排登记时，这份登记约 M 分钟后可以游玩。位置的详情把“这份登记”写成“这个位置”，并用这一行代替“受系统在两台机台之间安排登记的影响……”的通用说明。两个时间各写各的条件，不写成“N 至 M”：实际的等待在其中一个时间附近，而不是在两者之间任取 |
| 可能不准确时的说明（能写一句话的地方，只写一次） | 受系统在两台机台之间安排登记的影响，等待时间可能不准确，请以现场实际情况为准。 |
| 位置的时间早于前方的位置（前方有登记会被安排到另一机台，2026-11-28） | 受系统在两台机台之间安排登记的影响，这个位置预计早于前方的部分位置游玩。登记菜单写“这份登记预计早于前方的部分登记游玩。” |
| 前方有待签到的线上登记，未签到时明显更早（2026-11-26 定） | 前方的线上登记未按时签到时，这份登记最快约 N 分钟后可以游玩。位置的详情把“这份登记”写成“这个位置”；不到 1 分钟时写“可能很快可以游玩”。估时本身按线上登记都会签到计算 |
| 管理端队列一行 | 第 N 位·预计 N 分钟；可能不准确时写“第 N 位·最快 N 分钟” |
| 加入前的新登记预计等待 | 约 N 分钟；不到 1 分钟时写“很快可以游玩”。它是居中的估计，不用“最快”。例外（2026-11-27）：勾选了“允许系统在当前机台和 机台 B 之间安排登记”、且另一机台的时间更早时，写“最快约 N 分钟”，取两台机台中较早的时间 |
| 登记块上的预告 | 可能转至 B2：另一机台显示了这份登记的预览时写出位置编号，没有时写“可能转至 机台 B” |
| 登记菜单（终端、网页端）里的预告句 | 机台 B 的位置 B1 已显示这份登记的预览，最早 21:30 之后，这份登记可能自动转至该位置，请合理安排时间。没有预览位置时写机台，与原句相同 |
| 手动转至后的横幅标题 | 登记已转至位置 B3；不在同一个位置时写“登记已转至 机台 B” |

位置编号的用法（维护者，2026-11-25：“合理引用位置编号”）：写给此刻看的文字（登记块、登记菜单、操作后的横幅）写位置编号；事后才看的文字（日志、QQ Bot 私信）和讲规则的说明写机台，因为位置编号会随队列前移而变化。“位置 B1”前面紧跟中文时不空格，只有程序填入的机台名称前空一格。

### 延后的限制和上限（2026-11-25 定）

| 情况 | 写法 |
| --- | --- |
| 暂缓一次用过、尚未游玩一轮（灰色的原因，终端、网页端、Bot、服务端同一句） | 这份登记已暂缓过一次，游玩一轮之后才能再次暂缓。 |
| 已签到、尚未游玩的线上登记（同上，四处同一句） | 已签到的线上登记在游玩一轮之前不能延后。 |
| 轮空次数上限 | 平时不写。很少有人连续轮空三次（维护者：“不用强调三次退出，直到第三次轮空时才特别强调”），只在接近时写：已轮空 2 次时“……已轮空 2 次，这次将是第 3 次。此后再轮到时，如果仍设置了轮空一次或暂时离开，登记会被自动移除。”；已轮空 3 次时“……已轮空 3 次。下一次轮到时，登记会被自动移除，而不会移至队尾。” |

等待时间的取整和写法由维护者定（2026-11-28 修改）：45 分钟以内精确到 1 分钟，45 至 90 分钟精确到 5 分钟，90 至 120 分钟精确到 10 分钟，120 分钟以上一律写“2 小时以上”。60 分钟及以上写成“X 小时 X 分钟”，分钟为 0 时不写（“约 1 小时”“约 1 小时 15 分钟”“约 2 小时”）。“2 小时以上”前不加“约”或“最快”，例如“2 小时以上后可以游玩”。终端、管理 App 和网页端用同一个写法（终端 `formatWaitAmount`，网页端 `waitEstimateCopy.js` 的同名函数）。依据见 `docs/releases/wait-estimate-2026-11.md` 第十五节。

估计时间还没按当前队列算完时，不显示旧数值：登记菜单的小字不写等待时间，其他地方写“正在估算”（维护者 2026-11-28）。

机台停止使用的原因选“其他原因”并填写了说明时，显示填写的内容本身，不写“其他原因（……）”；没有填写时写“其他原因”（维护者 2026-11-28）。

## 句式

沿用现有文案里已经固定的句式。（现状）

| 用途 | 句式 | 例子 |
| --- | --- | --- |
| 操作的后果 | 确认后，……；转入后，…… | 确认后会解除固定组合，另一份登记继续留在游玩位置。 |
| 状态期间的规则 | ……期间不…… | 暂时离开期间不参与游玩组合。 |
| 本次选择的结果 | 本次将…… | 本次将使用“单人游玩”。 |
| 规则性的行为 | ……会…… | 两份登记会在队尾组成固定组合。 |
| 要求对方操作 | 请……；请先…… | 请先选择本次游玩偏好。 |
| 不可用的原因 | 系统规则不允许……；……暂不能…… | 系统规则不允许暂缓一次。 |
| 选项的说明 | 每次使用这份资料……时，…… | 每次使用这份资料创建登记时，再选择本次游玩偏好。 |
| 预览 | 预览不会改变真实队列。 | |

规则性的行为用“会”，本次选择即将产生的结果用“将”。

分句之间用分号连接，不用“并且”“但是”展开成长句。

## 标点与空格

1. 只用全角标点。（现状）
2. 中文与数字、英文之间空一格：30 分钟、QQ Bot、轮空 3 次。（现状）
3. 程序填入的机台名称，前面紧跟中文时空一格：转至 机台 B、在 机台 A 排队、加入 机台 A。名称在句首时不空。（已定，2026-11-24）
4. 引号用“”。（现状）
5. 完整的句子以句号结尾。标题、按钮、标签、选项名不加句号。（已定）
6. 确认弹窗的标题用问句，以问号结尾：转至 机台 B？（现状）

## 各类文字的写法

| 类型 | 写法 | 例子 |
| --- | --- | --- |
| 页面和弹窗标题 | 名词短语或动宾短语，不加句号 | 选择本次游玩偏好 |
| 确认弹窗标题 | 问句 | 创建朋友登记？ |
| 按钮 | 动词或动宾短语 | 取消、返回、关闭、我知道了 |
| 选项名 | 与用词表一致 | 单人游玩、允许他人加入、每次询问 |
| 说明小字 | 一到两个完整的句子 | 这份登记将独自占用一个等待位置。 |
| 按钮大标题下方的小字 | 属于说明小字：完整的句子，带句号；大标题本身不加句号（2026-11-23 定） | 单人游玩／这份登记将独自占用一个等待位置。 |
| 置灰原因 | 一个完整的句子，说明为什么不能用 | 处于游玩位置的登记不能转至其他机台。 |
| 错误提示 | 先说发生了什么，再说要做什么 | 现场队列已经更新，请刷新后重试。 |
| 日志标题 | “对象 + 已 + 结果”，不加句号。属于某台机台的日志，标题前写机台名和“：”，标题内部用“，”分隔 | 登记已转至 机台 B；机台 A：未到场，已移至队尾 |
| 倒计时 | N 秒后…… | 5 秒后可以关闭 |

## 同一件事只写一句

同一件事在终端、管理后台、网页端、Bot 和服务端里用同一句话。新增文案前先搜索是否已经有说同一件事的句子；有就原样使用。

### 不能改的服务端提示

以下服务端提示被已经发布的终端、网页端或 Bot 逐字比较，改动会让旧版本的兼容处理失效，所以保持原样，也不补句号：

- `不支持的队列数据版本`、`不支持的队列协议版本`（终端据此降级数据版本）
- `移动设备登记会话参数不完整`（终端据此改用旧接口）
- `请求包含不支持的排队操作字段`、`请求包含不支持的线上登记字段`（Bot、网页端据此去掉新字段重试）
- 含“只包含 bot_qq”“不能包含未知字段”的句子（Bot 据此判断服务端版本）

服务端常量 `COMMAND_TIMEOUT_DETAIL` 和 `LEGACY_COMMAND_TIMEOUT_DETAIL` 被数据库迁移按原文匹配；改前者时要把旧文字加进后者能识别的范围。
